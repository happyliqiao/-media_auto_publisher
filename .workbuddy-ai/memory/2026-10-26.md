## 云端运行改造（提交 f3f1139，已推送）
用户希望「电脑不开机也能跑」。结论：生成环节可完全交给 GitHub Actions（免费），但**头条自动发布必须有一台常开的云服务器**——Actions runner 临时的、IP 是数据中心地址，存不住登录态也过不了风控。

新增：
- `.github/workflows/generate.yml`：每 3 小时云端生成，产物上传 Artifact + 写入运行摘要，支持手动触发与 `MAP_PUBLISH_HOURS` 覆盖。
- `deploy/install_cloud.sh`：一键装依赖 → 建 venv → 装 Playwright Chromium → 装 systemd → 开机自启 → 生成 VNC 密码。
- `deploy/systemd/`：xvfb / fluxbox / x11vnc / novnc / media-auto-publisher 五个单元。
- `deploy/README.md`：方案 A 全托管云服务器 / 方案 B 仅 Actions / 方案 C 混合。

代码改造：
- `toutiao_browser.py`：区分 Windows / Linux。Windows 仍走 Edge + CDP 9223；Linux 走 Playwright `launch_persistent_context`（需 DISPLAY，由 Xvfb 提供），`authorize` 在 Linux 下会阻塞等待人工在 noVNC 里登录。
- `main.py`：`load_config` 支持 `MAP_STORAGE_DIR` / `MAP_DRY_RUN` / `MAP_TIMEZONE` / `MAP_PUBLISH_HOURS` 覆盖。
- `storage.py`：未过审稿件改存 `_rejected/`，`recent_texts` 跳过 `_` 前缀目录，不污染查重基线。

验证：两次连续 `run-once` —— 第 1 次过审并入正式存档，第 2 次（同一小时、内容重复）被查重拦下（相似度 1.00），落入 `_rejected/` 且不进入发布队列。
