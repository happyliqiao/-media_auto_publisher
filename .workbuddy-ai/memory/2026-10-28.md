## 排查「程序没有自动运行」

用户反馈自动发布没跑。查出三个叠加故障，任一都足以让整条链路停摆：

1. **计划任务指向不存在的路径**
   任务 `AI_Content_AutoPublisher` 的执行命令是
   `E:\media_auto_publisher\start_daemon.ps1`，项目实际在
   `E:\liqiaobac\-media_auto_publisher`。任务今天 10:02 确实被登录触发，
   但找不到脚本直接失败（LastTaskResult 非 0），且从未生成过 `logs/daemon.out.log`。

2. **`install_startup_task.ps1` 语法错误，从未成功执行**
   第 7 行 `-Argument "... -File \`"$ProjectDir\start_daemon.ps1\`"` 少一个结尾引号，
   整个脚本无法解析（"字符串缺少终止符"）。所以「注册开机自启」这一步一直是空转，
   现有任务其实是更早的旧路径残留。

3. **`start_daemon.ps1` 启动环节崩溃**
   本机进程环境里同时存在 `http_proxy` / `HTTP_PROXY`、`https_proxy` / `HTTPS_PROXY`
   （大小写各一份，值都是 `http://127.0.0.1:53611`）。这会让 PowerShell 的
   环境变量提供程序抛「已添加了具有相同键的项」，连 `Get-ChildItem Env:` 都失败，
   `Start-Process` 直接 ArgumentException —— 脚本在启动 python 前就退出了。

  绕开 `Start-Process` 的重复环境变量崩溃；解释器改为固定候选列表（不再递归扫描，

## 下半场：改成无需 Key 的组合式生成

用户问「必须要 KEY 么，能不能接免费模型」。查了本机：

- 没有 Ollama / LM Studio，内存 5.9GB 总 / 可用 0.6GB，**本地跑模型不可行**
- 两个 `.env` 里都是同一个 DeepSeek key，余额为 0

### 做了什么

`content_generator.py` 重写成两套生成器：

1. **compose（默认，零依赖零成本）**
   素材池：24 个小节（每节含小标题 + 两段正文）、8 个开头、8 个过渡句、8 个结尾、24 个标题。
   每篇抽 6 个小节（按素材池原顺序排列保证连贯），标题避开近期用过的。
   实测连续 60 篇：相似度上限 0.55（阈值 0.65），字数 709–869，**全部过审**。
   素材池从 18 节扩到 24 节后，相似度上限从 0.588 降到 0.550；加过渡句把字数下限从 697 抬到 709。
2. **大模型**：标准库 urllib 调 OpenAI 兼容接口，内置 deepseek / zhipu / siliconflow /
   openrouter 四个预设，`provider` 填名字即可，不用装 `openai` 包。
3. **auto**：按 zhipu → siliconflow → openrouter → deepseek 找可用 Key，全失败回退 compose。

`main.py` 的 daemon 增加「启动时先补发队列积压内容」：否则每次重启都会新生成一篇，
把队列里没发出去的旧稿变成孤儿。

### 计划任务又改了一版

上一版让任务跑 `start_daemon.ps1`（PowerShell 启动器），实测会卡住不返回。
最终改成**任务直接执行 `pythonw.exe -u main.py daemon`**，带 `-WorkingDirectory`，
彻底不经过 PowerShell。`install_startup_task.ps1` 只负责注册时探测带 playwright 的解释器。
`pythonw` 没有控制台窗口，日志全靠 `main.py` 自己写 `logs/daemon.log`。
